Is the task tool earning its keep?

All pi sessions across 5 repos, 9–10 September 2026. Source: session JSONL logs and .git/pi/task-log/tasks.

Short answer: it is a write-only diary right now. 19 tasks were created in two days. Two of them were ever opened by a second session. The other 17 were written, closed, and never read again.

The tool cost about 45,000 tokens of context across 21 sessions. The payoff was 2 real resumes plus 31 file references that a git log would also have given you.

It is not useless. It is mistuned. The write path is heavy, the read path barely runs.

What I would change

ordered by payoff per unit of effort
1
Create a task only when work will cross a session boundary 17 of 19 tasks were born and buried in one sitting. Trigger on: the work is paused, blocked, waiting on you, or spans a day. Otherwise the todo tool already covers it. That alone kills roughly 70% of the cost.
2
Make list cheap and conditional Change the AGENTS.md rule from "before substantial work, list active tasks" to "list only when resuming, or when the user references earlier work". Have list return active and waiting tasks by default, never done ones. This session's list returned 12 tasks; 9 were closed.
3
Auto-expire zombies Two tasks have sat active with zero entries since August. Any task with no entry for 7 days should go stale and drop out of list.
4
Stop writing decision entries mid-session 17 were written, none were read by another session. Fold the one that still matters into the final handoff. Decisions that shape the repo belong in an ADR, not a task log.
5
Keep handoff, but make it the only write One structured handoff at pause time, with references. That is what the two successful resumes actually read. Everything else in the log was decoration.
6
Merge the two ledgers, or make the boundary explicit 17 sessions ran todo and task_manage side by side. Either the task log absorbs the todo list, or AGENTS.md states plainly: todo is for the current sitting, task is for crossing a session boundary, never both for the same work.
