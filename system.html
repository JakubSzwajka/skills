You talk to one agent. It runs the rest.

The human talks to one orchestrator, and the orchestrator talks to engines. A lane now runs two ways: a pane you can watch, or a headless process that outlives the session that started it. What survives either one is the handoff file and the central spec record.

the boundary

One conversation in front, engines behind it

You never join a worker's session and never read its terminal to find out what happened. When a worker needs judgement, it reaches you through the orchestrator, in your own conversation. That boundary is the point of the whole thing, and every mechanism below exists to hold it.

The human talks to one agent. That agent talks to the workers.

two ways to break it
  • Adding a mechanism you have to operate. If a change means watching a pane, opening a log, or chasing a worker, the rule is already broken.
  • Losing the record. Work whose reasoning survives only in a chat window gets redone.
one central record

Specs have one store, one lifecycle, and a master-only mount

Every spec lives under ~/.pi/specs/. Machine state stays in spec.json; human intent stays in SPEC.md. Tickets, research, prototypes, and durable log entries join the same folder only when used. The master mounts the whole spec. Children receive self-contained briefs, never the mount.

/to-spec
Synthesizes the current conversation without another interview. Invocation authorizes creation, starts status at pending, and writes no remote issue.
/to-tickets
Writes approved tracer-bullet slices under the central spec's local tickets/. Remote issues can supply requests, but there is no mirror or sync.
/spec
Lists all pending specs and done specs completed in the last 72 hours. A mounted spec stays mounted and listed after completion, regardless of age.
master and children
The mount exists only in the master session. A child gets the relevant intent, constraints, and checks in its brief. Research and prototype lanes may also receive one exact owned output path.

the child boundary is deliberate

The spec-link extension registers nothing in delegate children, including its log tool. The master reads the record and writes a self-contained brief. A child must not browse the central folder to reconstruct missing context.

  2. Split when needed. /to-tickets writes approved local slices. Their progress never changes spec status.
  3. Mount in the master. /spec adds a short pointer to the orchestrator's context without copying file bodies.
  4. Brief the child. Give it the needed intent and checks, not a direction to inspect the whole spec.
  5. Keep only durable history. Log approvals, amendments, rejected choices, material discoveries or scope changes, verifier outcomes, and completion or reopening.
what stays out of the log

Do not log prompts, ordinary tool calls, every test, generated files, ticket boxes, or routine handoffs. A repository-hosted prototype gets one central record with its exact code path and verdict. Existing .scratch records stay untouched as legacy data; no new spec is written there.

execution

Delegate runs depth-one sessions and returns a file

Four actions, no polling. start writes the lane record before anything is running, so a spawn that half fails still leaves a lane you can address. The worker writes its assigned handoff and rings through intercom, which fires your next turn. Intercom is the only completion wake. You read, verify, and stop. The tool owns the return contract, the handoff path, and the doorbell line; a brief that writes them by hand gets them wrong.

the widget
One row per live lane above the editor, under a muted rule. It repaints on a 1.5 second timer rather than at turn boundaries, so context use and spend move while you work. Most ticks read files only; every fourth one asks each transport for statuses. A lane that needs you paints in the error colour and the header counts it.
the ring
The worker messages the parent through intercom when its handoff is written. That fires your turn. Polling costs more context than every worker answer combined, so the ring is the wake.
blocked
The most expensive state on the board. A pane reports it for any approval or question. A headless lane only gets it from an intercom ask that expects a reply, and it clears itself once the worker's transcript grows again.
adoption
The registry is a file, so a lane outlives its orchestrator. A fresh session claims lanes in the same directory only after the previous parent's process is confirmed gone. Until then they list as another parent's and cannot be read or stopped.
one narrow mutation path

/commit [instruction] gives commit work to an isolated model

Running /commit is approval for one commit. Its optional text is the first scope hint; the active parent thread is always the fallback. The worker inspects the repository and refuses when it cannot separate the requested paths from unrelated work.

first model
openai-codex/gpt-5.6-luna. It gets an in-memory session with project resources disabled.
fallback
openrouter/anthropic/claude-haiku-4.5, after a Luna setup or provider failure before any Git mutation, or after Luna submits an invalid commit message before mutation. Once staging starts, fallback is forbidden.
live status
/commit  luna  4.2s, then staging  3 files with indented paths. Direct Git-tool callbacks move the phase through inspecting, staging, and committing. A 100 ms timer repaints elapsed time only; it does not poll the model. Success, failure, abort, and session shutdown clear the widget.
tool boundary
read, git_snapshot, git_stage, and git_commit. No shell, edit, write, delegate, amend, push, hook bypass, reset, or restore.
Git guard
An exclusive lockfile beside the resolved active Git index binds /commit runs through preflight, snapshot, staging, and commit. Final symlink chains, including dangling chains, resolve with loop detection before a missing target falls back to its canonical parent plus target filename. The complete holder file appears through an atomic hard link. process.pid appears in the temporary filename and holder JSON only as a diagnostic; it is never used for liveness or reclamation. An existing lock is never inspected or reclaimed: the run refuses at once with its absolute path and the exact rm command, even when the Git directory is not writable. A crash leaves lock cleanup to the operator and may leave a unique temporary file that the operator may delete. Ownership is guaranteed against other /commit runs. Removing a live lock by hand voids that guarantee. The guard does not exclude plain git add or other Git commands run elsewhere. Mutating tools run in sequence, hooks run, and a moved HEAD stops the commit.
one seam, two runners

A pane you can watch, or a process that outlives you

Both paths share the registry, the assigned handoff, the intercom ring, the return contract, and the depth-one guard. transport is a field on a profile, and it defaults to herdr. It is not a start argument. No profile sets it today, so every lane is a pane until the operator changes a profile.

when a lane reads unknown

Nothing nags about this state, so it is on you to look. A headless lane reads unknown when ps could not be read or the record carries no process start time. A pane lane reads it when the pane is there but Herdr lists no agent in it. The record stays open, and stop on a headless lane refuses to signal and hands you the pid, the log and the kill command to run yourself. Signalling a pid that may have been recycled would kill a stranger's process group. Until you know which it is, do not start a replacement lane on the same paths.

give it a pane
  • You may want to watch it, or read the pane when it goes quiet.
  • It needs a project-local skill, extension or setting. Print mode never prompts for trust, so those are skipped.
  • It is the one thing you are doing right now.
run it headless
  • The work has to outlive this session, and a fresh parent will adopt it.
  • Panes would crowd the screen.
  • There is no Herdr to run in. Only the pane transport refuses; headless lanes still start, list, read and stop.
remaining gaps

Two things this system still does not do

The central spec now holds intent, lifecycle state, local tickets, and durable history. The open gaps are runtime controls: steering an active lane and starting work from an external signal.

what is not a gap

A cross-project view of everything running sits outside this repository on purpose. That is the terminal tool's job, not an agent's.
