# Findings 2026-09-09: orchestration is working, but it is slow

Scope: all 15 parent sessions and 107 child runs from 2026-09-09, the first full day after
`AGENTS.md` made delegation the default. Raw data:
[`baselines/2026-09-09-orchestration-latency.json`](baselines/2026-09-09-orchestration-latency.json).

Quality was fine. Speed was not. One in four child runs died, and 45% of all child
compute went into 15 long runs that mostly had to be redone.

## The seven patterns

### 1. Deadlines cut workers off mid-edit

11 runs hit their deadline. They were not idle. The 16:10 worker was writing
`apps/site/src/styles/place.css` three seconds before the kill. The 19:18 worker was
inside `npm run check && npm run build`. The deadline lands wherever the child happens
to be, so the parent inherits a half-applied diff and no handoff.

Cost today: 251 minutes of child time, plus every recovery run that followed.

### 2. Recovery chains serialize the whole day

The 16:32 order-buddy session is the clearest case. One landing page took 8 launches
in a row, each waiting on the last:

```text
16:48  worker, 4 lanes, 30 min deadline ──► TIMEOUT at 17:18, 15 files half-done
17:19  resume attempt 1                  ──► never reached ready, no changes
17:22  resume attempt 2                  ──► finished
17:29  fresh reviewer                    ──► 3 findings
17:36  resume writer to fix              ──► done
17:46  final verifier (unbounded)        ──► TIMEOUT after 10 min
18:09  final verifier (bounded, delegate)──► passed in 4 min
18:47  round two on owner feedback       ──► ...
```

Two hours of wall clock, one page. Nothing here ran in parallel because each step
needed the previous step's result.

### 3. A typo in a handoff path costs 20 minutes

The 17:46 verifier brief contained
`--Users-jakubszwajka-DEV-priv/order-buddy--`. The real directory is
`--Users-jakubszwajka-DEV-priv-order-buddy--`. One slash.

The reviewer then spent its entire budget hunting: 33 reads, 27 `ls`, 7 `find`,
8 `grep`, and 39 references to the broken path before the deadline killed it. The
rerun at 18:09 with an explicit file list passed in 4 minutes.

28 of this project's children read another child's output through a pasted absolute
path. The tool already returns `outputReference` and `outputPathMapping`. We are not
using them.

### 4. Model diversity is nominal, not real

Reviewers were routed to `anthropic/claude-opus-5:high` to get an independent family,
exactly as A1 asks. Opus worked until 16:25. From 17:18 onward all 14 attempts hit a
429 and fell back to `openai-codex/gpt-5.6-sol:high`.

So the last third of the day had zero cross-family review while the logs still claim
Opus was requested. The fallback is silent. That is worse than not trying, because the
integration report reads as if two families agreed.

### 5. Long model stalls with nothing running

105 gaps over 60 s with no tool in flight, 247 minutes total. Six of them ran past
10 minutes, including three at roughly 16 minutes each. No tool call, no output, no
error. The child then resumed normally or died on its deadline.

I cannot tell from the logs whether this is provider queueing, a stream hang, or a
client retry that is invisible in the transcript. It deserves a direct check against
pi's provider layer, because 247 minutes is the single largest line item.

### 6. Children rewrite whole files instead of editing

One child wrote `pi/extensions/task-log/index.ts` five times in a row: 74 s, 76 s,
81 s, 109 s, 218 s. Each write regenerates the full file. The worst single write, an
output handoff, took 17 minutes.

Whole-file `write` on a large file is a latency bomb. `edit` exists for this.

### 7. Control-plane fumbles on the parent side

Small individually, annoying together. 26 failed control calls today:

| Symptom | n |
| --- | --- |
| workflow reported `State: failed` | 12 |
| child launch failed at startup | 7 |
| `Async run not found` | 4 |
| `cannot carry the attached task identity` | 3 |
| `Interrupt is unsupported, use stop` | 2 |
| steering delivered but never acknowledged | 2 |

Two of the `Async run not found` calls used corrupted ids: `db7ebwrapped? no` and
`db7eb32c-e039- aanvragen`. The parent model garbled a UUID mid-token. Both wasted a
round trip.

The `task identity` refusal happened three times in three different sessions. Same
mistake each time: a foreground child launch while a task is attached. That is a rule
the parent has to learn once, not three times a day.

## What I would change first

Two items, per the audit rule of at most two mechanisms per iteration.

- [ ] **B1. Make the deadline a soft budget, not a guillotine.** A worker should get a
      warning at 70% of budget with instructions to stop, write its handoff, and return.
      Today a timeout destroys the return value even when the work is nearly done.
      Evidence to collect: zero timeouts that discard completed edits over the next ten
      writer runs.
- [ ] **B2. Never paste an artifact path by hand.** Pass `outputReference` or
      `outputPathMapping` between lanes. When a path must be literal, the parent verifies
      it exists before launching, and the brief tells the child to fail fast rather than
      search. Evidence to collect: no child spends more than three tool calls locating an
      input, over the next ten handoffs.

Held for the next iteration, in order:

- [ ] Make provider fallback loud. When Opus 429s into gpt-5.6-sol, the integration
      report must say the review was single-family.
- [ ] Cap read-only reviewers to a named file list. Both timed-out reviewers were
      unbounded explorers.
- [ ] Ban `find` and `grep` over `$HOME`, `~/.agents`, and `node_modules` in child briefs.
- [ ] Instrument the silent model stall before spending more time on prompt-level fixes.

## Relation to PLAN.md

A1 is working in the sense that delegation happens by default. It is not yet working in
the sense that it saves time. A3 (self-contained briefs) and A4 (bounded result
transport) are the two open items this day's evidence hits hardest: the path typo and
the unbounded verifier are both brief defects, not model defects.
