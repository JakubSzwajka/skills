These numbers measure behavior visible in historical sessions. They do not prove that the current setup still behaves the same way. Some current global rules already cover habits that the assessment counted as operator misses.

## Executive finding

The operator directs the main agent very well. Outcomes, constraints, evidence, corrections, decision rights, and risk calibration are strong.

The weak seam is between the main agent and delegated workers:

```text
operator
  strong outcome, evidence, boundaries
    main agent
      strong steering and recovery
        delegated workers
          weak ownership and handoff contract
        integration
          often main-agent-led and implicit
        final proof
          not always independent
```

The setup should keep its main-agent workflow and improve five worker mechanisms: ownership, self-contained briefs, bounded result transport, visible reconciliation, and independent proof.

## What is good

### Main-agent direction

The operator usually opens with an observable result, not a list of steps. The main agent can choose an implementation while still knowing what must be true at the end.

### Evidence and correction

References consistently resolve and influence the work. When an answer or implementation misses, the correction names the mismatch and preserves the objective instead of replacing it with a new task.

### Decision boundaries

Commit, push, publish, release, deployment, deletion, messaging, and tracker writes are treated as distinct decisions. Safe investigation can proceed with autonomy while consequential actions return to the operator.

### Learning and recovery

Failed approaches are usually reversed rather than defended. Important decisions and repeated failures often become durable records, rules, tests, or runbooks.

## What needs work

### Parallel ownership

Workers are sometimes launched without an explicit owner for each area, a shared-state rule, or a named integration owner. The improvement is a mandatory delegation plan before fan-out; the main agent should not launch parallel writes until ownership and isolation are clear.

### Self-contained worker briefs

A fresh worker sometimes receives the task but not the reason, stop conditions, or context it cannot inherit. Every brief should carry outcome, inputs, ownership, non-goals, stop conditions, acceptance, and return format.

### Result transport

The baseline assessment exposed this directly. Large worker JSON responses were truncated, so the scoring work had to be repeated with compact aggregates. Large results should become local artifacts with a summary, schema version, path, and checksum.

### Visible integration

Worker returns are often blended by the main agent without showing disagreement or rejected findings. The integration owner should list agreements, conflicts, rejected findings, the chosen decision, and who made it.

### Independent final proof

The same agent that implements a change often runs the check and declares success. Significant work should end with proof after the final mutation through a different channel when practical.

### Explicit delegation policy

Low operator-initiated delegation is not automatically bad. Autonomous delegation is part of the intended setup. What is missing is one written policy for when the main agent may delegate, how many workers it may launch, and when approval is required.

### Rule ownership

The setup has strong safeguards spread across system rules, global instructions, repository rules, skills, and task contracts. Each behavior should have one owning layer and an explicit precedence order so workers receive only the rules they need.

## Detailed observations

1. **Intent clarity.** Opens work with an observable outcome in 216 of 226 eligible episodes, so the agent usually knows what success should look like before choosing steps.
2. **Problem framing.** Frames the underlying problem or goal in 170 of 172 eligible episodes, and changes direction when evidence makes the first prescription look wrong.
3. **Agent state modeling.** Usually accounts for what a fresh session, delegated worker, or external environment can see instead of assuming context crosses those boundaries.
4. **Context anchoring.** Supplied references resolved and influenced the work in every eligible episode, which keeps requests tied to real evidence rather than remembered summaries.
5. **Constraint precision.** States preserved behavior, exclusions, and approval boundaries in 193 of 195 eligible episodes, especially around publishing and destructive actions.
6. **Falsifiable acceptance.** Usually defines checkable acceptance before work begins. The habit appeared in 196 of 205 eligible episodes, and 152 reached an independently observed outcome.
7. **Understanding before repair.** Usually asks for reproduction, tracing, or a tested hypothesis before repair, though 19 eligible episodes moved ahead without that grounding.
8. **Root-cause orientation.** Chooses mechanism-level repairs in 93 of 98 eligible episodes and generally rejects fixes that only hide the visible symptom.
9. **Evidence injection.** In 26 of 145 eligible episodes, the agent had to gather the decisive logs, measurements, or screenshots because the request did not supply them at the decision point.
10. **Progressive disclosure.** Adds context as it becomes useful in 109 of 117 eligible episodes, letting new evidence change the next step without front-loading the whole history.
11. **Context economy.** Keeps context focused and low in duplication in 158 of 168 eligible episodes, using short follow-ups more often than repeating the full request.
12. **Durable memory.** Turns decisions and recurring corrections into durable records in 95 of 102 eligible episodes instead of leaving the reasoning only in chat.
13. **Inspect before edit.** Misses an explicit inspect-before-edit request in 55 of 157 eligible episodes, so the agent often supplies this safety step rather than receiving it from the brief.
14. **Capability provisioning.** Usually provides the needed capability or permission with a clear scope, while keeping credentials and higher-impact access behind a separate decision.
15. **Delegation judgment.** Delegation was operator-initiated in only 31 of 89 eligible episodes. Most parallel research and worker spawning came from the agent rather than the request.
16. **Decomposition.** Breaks broad work into coherent, independently checkable units in 75 of 100 eligible episodes, especially when releases or multiple concerns are involved.
17. **Worker brief quality.** Delegated briefs were incomplete in 23 of 60 eligible episodes, most often because task-specific stop conditions or non-inheritable context were implicit.
18. **Decision rights.** States what the agent may decide and what needs approval in 141 of 153 eligible episodes, with strong boundaries around publication and external writes.
19. **Parallelism hygiene.** Parallel ownership or workspace isolation was missing in 49 of 69 eligible episodes, leaving collision prevention to agent defaults.
20. **Result integration.** Delegated findings were not explicitly reconciled into one operator-owned decision in 27 of 74 eligible episodes, so synthesis often stayed agent-led.
21. **Feedback specificity.** Every eligible correction preserved the objective while naming what was wrong, making feedback useful without restarting work unnecessarily.
22. **Trust calibration.** Adjusts autonomy and scrutiny to risk in 187 of 191 eligible episodes, granting broad freedom for safe exploration and reserving approval for side effects.
23. **Verification closure.** Final verification closure was missed in 50 of 166 eligible episodes. The agent often ran checks, but the request did not always demand a post-change independent confirmation.
24. **Recovery and learning.** Reverses failed approaches and captures lessons in 66 of 72 eligible episodes, often converting a surprise into a rule, record, or repeatable safeguard.

## Recurring practices

1. Starts with the desired result, then narrows scope after seeing evidence instead of locking the agent into the first implementation idea.
2. Uses real references and staged follow-ups to keep context relevant while still allowing later evidence to change the plan.
3. Requests separate workers when concerns are genuinely independent, but usually lets the main agent decide whether delegation is worth it.
4. Asks for observable checks and often gates risky actions on passing output, health state, or a working end-to-end path.
5. Corrects mismatches with concrete expected behavior and keeps the original objective intact rather than replacing it with a new task.
6. Provides access and permissions only when needed, with separate approval for publication, external writes, and destructive operations.
7. Turns repeated manual checks into scripts, tests, hooks, or operating rules when the same failure is likely to return.
8. Moves decisions, rationale, and recurring corrections into durable records so later sessions do not depend on conversational memory.
9. Stops defending a failing approach once evidence changes, then narrows, reverses, or restarts without abandoning the intended outcome.
10. Treats commit, push, release, deployment, messaging, and deletion as distinct actions with distinct approval boundaries.

## Recurring costs

1. Delegation initiation stays with the agent, so worker count and research breadth can grow before the operator has chosen whether parallel work is useful.
2. Concurrent work sometimes starts without named ownership or isolation, making collision prevention dependent on agent defaults.
3. Inspection before mutation is not always required by the request, so the agent chooses whether to verify current state first.
4. Agent-run checks are sometimes accepted without independent confirmation after the last change, leaving closure claims under-proven.
5. Worker briefs sometimes omit stop conditions or non-inheritable context, creating avoidable clarification or drift.
6. Worker returns are sometimes reconciled without an explicit final trade-off, allowing useful disagreement to disappear inside synthesis.
7. Decisive evidence sometimes arrives after investigation starts, which forces reframing or repeated work.
8. Durable capture is strong overall, but rationale and rejected alternatives are less consistent than the final decision itself.

## Target collaboration shape

```text
operator
  state outcome, constraints, and decision rights
  authorize consequential actions

main agent
  inspect and frame the problem
  decide whether delegation has real value
  publish a delegation plan
    worker ownership
    shared-state and isolation rule
    output schema and size limit
    stop and escalation conditions
  launch workers
  reconcile agreements and conflicts
  record the chosen decision
  run an independent final check
  report evidence and remaining risk

worker
  receive a self-contained brief
  own one bounded area
  return a compact result or artifact pointer
  stop on boundary violation
```
